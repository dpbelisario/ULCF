1. What this package is

The title above is the working title of the paper that you will write. You are not expected to understand it yet: the pages of this package explain every term in it. The package holds three kinds of material.

  • read Pages to read: 15 HTML pages in docs/, in addition to this one. They explain the research theme, the background knowledge, and the three switches that the research compares.
  • given Code to run: complete MATLAB code in matlab/ that passes its own tests. It consists of a library (a folder of functions that the scripts call), six demo scripts for the background pages, and the simulations of two baseline switches. A baseline is an existing design with which a new design is compared.
  • yours Code to build: three task files in matlab/work/ for the proposed switch, which is the new design. Each file states a task and holds no solution. Writing this code is the main part of your research.

You do not read all pages first and run all code afterwards. Go through Fig. 1 row by row: read the pages of a row and work with the code of the same row before you go on to the next row. Section 3 gives the exact order.

2. Set up in three steps

You need MATLAB R2020b or later. You need no toolbox: the code uses base MATLAB only. The package was tested with MATLAB R2025a on Windows.

  1. Unzip the package. Unzip the file that you received. Find the folder that contains START_HERE.html, docs and matlab. Put this folder in a place whose path contains no spaces and only ASCII characters: English letters, digits, _ and -. The examples on this page use C:\research\clos_ulcf. With a space in the path, the command cd of step 2 fails. The limit to ASCII characters is a precaution against problems with folder names. Do not move or rename anything inside the folder. Open START_HERE.html from this folder in a web browser. The pages work without an internet connection.
  2. Set the MATLAB path. The search path is the list of folders in which MATLAB looks for functions and scripts. Start MATLAB, make the folder matlab of the package the current folder, and run setup_path. 
    >> cd C:\research\clos_ulcf\matlab
>> setup_path
MATLAB version : 25.1.0.2973910 (R2025a) Update 1 (this package needs R2020b or later)
Package folder : C:\research\clos_ulcf\matlab
Path is set (lib, demos, main, work, tests).
    The first two output lines show your MATLAB version and the place of your folder matlab, so they differ on your PC. The path setting is not saved. Run setup_path again every time you start MATLAB.
  3. Test the library. Run run_all_tests. It checks every function of the library, takes less than a minute and prints about 50 lines. Two figure windows open for a moment and close again; this is part of the test. Below, ... stands for lines that are left out. 
    >> run_all_tests
Check 1 passed: attenuation
Check 2 passed: calc_signal_power
...
test_lib_power_loss: all passed
...
test_lib_filters_qam: all passed
...
test_lib_edfa: all passed
All tests passed.
    The last line must be All tests passed. If a check fails, MATLAB stops at this check and prints the reason in red. In that case do not go on. Look at the troubleshooting table in section 7 of page 04. If that does not help, send the complete red text to your supervisor.

Copy before you change

There are two kinds of change in a demo script or in a script of matlab/main/.

  • You try a value. The pages and the script headers ask you to change a parameter value in section 1 of a script and to run the script again. Do this in the given file, and set the value back afterwards.
  • Every other change. Save a copy of the script in matlab/work/ under a new name, for example my_step21.m, and change the copy. The new name is necessary: matlab/demos/ and matlab/main/ come before matlab/work/ on the search path, so MATLAB can run the original in place of a copy with the same name.

If you are not sure that a given file is still the original, take it from the zip file again.

5. Working rules

These five rules keep your results reproducible. Reproducible means that you, or another person, can obtain the same result again later.

  • Keep run_all_tests passing. Run it on the first day, and again whenever you suspect that a given file has changed. A result that was produced while a test fails is not valid. Every test script starts with clear; close all, so run_all_tests deletes your variables and closes your figures.
  • Never edit a number by hand. Every number in a table or a figure is the output of a script. If a number is wrong, correct the script and run it again.
  • Every figure comes from a saved result file. This holds for every figure that you show to another person. The result file stores the parameters and the seed together with the result. The seed is the number that you give to rng. It fixes the random numbers, so that a run can be repeated exactly. The two main scripts already work this way: each run saves a .mat file with all parameters, the seed and all results. Do the same in your own scripts.
  • Write down what you changed and why. Keep a notebook. For every run that matters, note the date, the script, the change, the reason and the name of the result file.
  • When a result surprises you, check a limit case before you believe it. A limit case is a setting for which you know the answer in advance. One example: without noise, the bit error ratio must be 0. Page 23 lists checks of this kind for your own code.
Done when
  • run_all_tests ends with All tests passed. on your PC.
  • You can say which folder is yours, and when you must copy a given script before you change it.
  • You can state the five working rules.
