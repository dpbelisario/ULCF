04MATLAB guide

The code of this package is plain MATLAB, like the code of your practice chapters. Some conventions are different, and the functions are now in files of their own. This page names the differences, shows how to read a library function, lists every given file, and tells you how to run the scripts and what to do when an error appears.

1. Set-up and the folder map

You did the set-up on the page Start here: make the folder matlab the current folder, run setup_path, then run run_all_tests. This section explains what setup_path does, because several rows of the troubleshooting table in section 7 go back to it.

The search path is the list of folders in which MATLAB looks for functions and scripts. When you type a name, MATLAB looks for it in this order:

  1. a variable of that name in the workspace (the workspace is the set of variables that exist at the moment);
  2. a file of that name in the current folder;
  3. the folders of the search path, from the top to the bottom.

setup_path puts five folders of the package at the top of the search path, in this order: lib, demos, main, work, tests. Three consequences follow.

  • Run it in every session. MATLAB does not save the path. After a restart the five folders are gone, and MATLAB does not find the library until you run setup_path again. Your variables stay: the script removes only its own variables, whose names start with setup_.
  • Stay in the folder matlab. The file setup_path.m is in matlab, and matlab itself is not on the path. Make matlab the current folder before you type setup_path, and keep it as the current folder while you work.
  • One name, one file. If two files have the same name, MATLAB uses the one that it finds first and ignores the other without a message. The earlier laboratory code has functions with the names of this library, for example attenuation and awg. setup_path therefore checks that MATLAB takes attenuation from this package. It stops with an error if that is not so, and it prints a note if a second copy is lower on the path.

setup_path also makes every new figure of the session light. MATLAB R2025a and later can draw figures with a dark background, and the black lines of the scripts are invisible there.

2. Conventions that differ from the practice chapters

The scripts keep the style that you know: numbered sections, plain variables, for loops, and self-checks with assert. Six conventions are different. Table 2 lists them.

Common mistake

Do not write x' to turn a row vector into a column vector. For complex numbers the operator ' also takes the complex conjugate, which mirrors the spectrum of a signal. Write x.' (transpose only) or x(:) (always a column). The given code uses .' everywhere.

3. How to read a library function

Every file in lib/ has the same layout: the function line, a block of comments called the header, the code, and end. Here is the complete file lib/attenuation.m.

function [y, att] = attenuation(x, loss)
%ATTENUATION  Apply a power loss given in dB to an optical field.
%
%   [y, att] = attenuation(x, loss)
%
%   Inputs
%     x     : optical field, one signal per column [sqrt(W)]
%     loss  : power loss [dB] (a negative value is a gain)
%             scalar, or a 1 x M row vector with one loss per column of x
%   Outputs
%     y     : attenuated field [sqrt(W)]
%     att   : amplitude factor that was applied (= 10^(-loss/20))
%
%   Legacy: attenuation.m (same name, same arguments).
%   Note: a POWER loss of L dB multiplies the FIELD by 10^(-L/20).
%   Example: a loss of 3 dB halves the power; the field is divided by sqrt(2).

att = 10.^(-loss/20);  % dB (power) -> amplitude factor
y = x .* att;
end
Table 4. The parts of a header, in the order in which they appear.
PartIn attenuation.mWhat it tells you
H1 line%ATTENUATION Apply a power loss ...The name of the function in capital letters and one sentence that says what the function does.
Syntax[y, att] = attenuation(x, loss)How to call the function. The outputs are in square brackets on the left, the inputs in parentheses on the right. The order is fixed.
Inputsx, lossFor every input: its meaning, its shape (one signal per column, a scalar, a row vector) and its unit in square brackets, here [sqrt(W)] and [dB].
Outputsy, attThe same for every output.
LegacyLegacy: attenuation.m (...)How the function differs from the function of the same name in the earlier laboratory code. Your supervisor needs this line. You can skip it.
Note, Examplethe last two comment linesProperties that are easy to get wrong, and numbers that you can check by hand.

Type help attenuation in the Command Window: MATLAB prints this header. Read it in this order: the H1 line, then the inputs and outputs with their shapes and units, then the notes. Read the code last. Three more commands are useful. which attenuation shows the file that MATLAB uses. edit attenuation opens this file in the editor. help step21_two_stage_one_point prints the title block of a script in the same way.

Now call the function. The comments show what MATLAB answers.

x = [1; 1i; -1; -1i] * sqrt(1e-3);   % four samples, each with a power of 1 mW
[y, att] = attenuation(x, 3);        % a loss of 3 dB
calc_signal_power(x)                 % -9.6433e-16, that is 0 dBm
calc_signal_power(y)                 % -3.0000 dBm
att                                  % 0.7079 = 10^(-3/20)

The first answer is not exactly 0, because a computer rounds every number to about 16 digits. For this reason the self-checks do not compare a computed power with ==. They allow a small difference, for example abs(P_x - PTx) < 1e-9 in demo12_units_power_budget. A simulated power that contains random noise gets a larger tolerance, for example diff_power < 0.1 in step21_two_stage_one_point. A function can return several outputs, and you ask only for those that you need: y = attenuation(x, 3) returns the first output only. A ~ in the list of outputs skips one, as in [signal(:, k), ~, ~] = TL_QAM(...) in step21_two_stage_one_point.

4. MATLAB idioms you will meet

Six patterns appear again and again in the given code. The examples below are copied from it. Only the three-line example at the end of this section was written for this page.

Filtering in the frequency domain

From lib/apply_filter.m:

% multiply the spectrum of every column by the mask
spectrum = fftshift(fft(expanded, [], 1), 1);  % 0 Hz in the middle, like H
spectrum = H .* spectrum;  % H (N x 1) acts on every column
signal = ifft(ifftshift(spectrum, 1), [], 1);  % back to the time domain

fft computes the spectrum of a block of samples: one value, called a bin, for each frequency. fftshift reorders the bins so that 0 Hz is in the middle. A filter is a vector H with one factor per bin, called a mask: the code multiplies the spectrum by it, undoes the reordering with ifftshift, and returns to the time domain with ifft. The arguments [], 1 and 1 mean "along dimension 1", that is down each column, so every column is filtered as one signal. Page 13 explains the method.

Logical masks

From lib/my_qamdemod.m, inside the loop over the constellation points k:

dist = abs(sym - constellation(k));  % distance of every sample to point k
closer = dist < best_dist;  % samples for which point k is the closest so far
sym_num(closer) = k - 1;  % symbol numbers start at 0, indices at 1
best_dist(closer) = dist(closer);

A comparison of two arrays returns an array of true and false values, a logical mask. Used as an index, the mask selects the elements where it is true: sym_num(closer) = k - 1 changes only these elements, without a loop over the samples. The filter functions build their masks in the same way, for example H = double(fc >= -width/2 - tol & fc < width/2 - tol) in nyquistfilter.

dB and linear numbers

From lib/calc_signal_power.m, lib/attenuation.m and lib/amplified_by_EDFA3.m:

power_W = mean(abs(signal_w).^2, 1);  % mean power of each column [W]
signal_power_dB = 10*log10(power_W*1e3);  % W -> mW -> dBm

att = 10.^(-loss/20);  % dB (power) -> amplitude factor

gain = 10^(gain_dB/10);  % power gain G, dB -> linear

10*log10(x) converts a power ratio to dB, and 10^(x/10) converts dB back to a power ratio. For a field the divisor is 20, because the power is the square of the field. In the second line, the factor 1e3 converts W to mW, because dBm means dB relative to 1 mW (page 12). Use log10: in MATLAB, log is the natural logarithm.

One signal per column

From block [3] of main/step21_two_stage_one_point.m:

for k = 1:dcs_input_port_num
    if k ~= target_port
        signal(:, k) = attenuation(signal(:, k), dcs_ex_ratio);
    end
end
signal = sum(signal, 2);  % output port of the DC switch: target + leaks

At this point of the script, signal is a matrix with datasize*up rows, one per sample, and dcs_input_port_num columns, one per signal: 60000 x 8 with the default values. signal(:, k) is column k, that is all samples of signal k. sum(signal, 2) adds along dimension 2, across the columns, and returns one column: the sum of all signals, sample by sample.

save writes the named variables into a .mat file. The script names every parameter, the seed and every result, so the file alone shows how the result was made. fullfile joins folder and file names. The time stamp makes every file name new, so a run never overwrites an older result.

The given scripts do not read a .mat file back; you will do that in your own scripts. Name the variables that you want. The next three lines are an example with matlab as the current folder. Use the name of your own result file.

load('results/two_stage_ULCF_20261005_181204.mat', 'required_PTx', 'ULCF_deg_ary');
A = readmatrix('results/two_stage_ULCF_20261005_181204_required_PTx.csv', 'NumHeaderLines', 1);
writematrix(required_PTx, 'work/my_table.csv');

load without a list of names brings back all saved variables and overwrites variables of the same name in your workspace, for example datasize. readmatrix reads a CSV file into a matrix, and 'NumHeaderLines', 1 skips the header line; the scripts in main/ read their reference files in this way. They write their CSV files with fopen, fprintf and fclose, because each file begins with a header line. For a matrix of numbers without a header, writematrix does the same in one line.

6. Running the scripts

A whole file or one section

A line that starts with %% begins a section. MATLAB gives you two ways to run a script.

  • The whole file: press F5 in the editor, or type the name of the script in the Command Window.
  • One section: put the cursor in the section and press Ctrl+Enter. You worked in this way in the practice chapters.

Four rules apply to the scripts of this package.

  • Run a given script as a whole file first. Every demo, every script in main/ and every test script begins with clear; close all; rng(1);. This line deletes all variables, closes all figures and sets the seed of the random numbers, so a whole run does not depend on what you did before. Save what you still need before you start a script.
  • Look at the variables afterwards. After a run all variables stay in the workspace. Type a name, for example stage_power after step21_two_stage_one_point, to see its value. You can also run one section again, for example the figure section of a demo.
  • After you change a parameter, run the whole file again. A section that runs alone uses the variables that are in the workspace at that moment, including results of the old parameter values.
  • Run the four scripts in main/ as whole files only. In the two step... scripts, the later sections compare the simulation of section 3 with a budget, that is with values that formulas predict. The comparison is valid only if all sections ran one after another with the same parameters. The two main_... scripts find the folders results and ref_data from the location of their own file, and MATLAB reports this location correctly only when the whole file runs. When only a section runs, section 1 can stop with a message that ends with The folder of this file is not known when a single section is run. MATLAB can also report a folder of temporary files instead; R2025a does this. The script then does not stop, does not find its reference file, and writes its results outside the package.

To stop a running script, click in the Command Window and press Ctrl+C.

Quick run and full-size run

The first parameter of both main_... scripts is quick_flag. With quick_flag = 1, the value in the given files, a run uses 30000 symbols for each operating point and tries the transmitter power in steps of 1 dB. With quick_flag = 0 it uses 150000 symbols and steps of 0.5 dB. Use the quick run to see that everything works and to learn how to read the output. Use the full-size run for a result that you keep. The .mat file stores quick_flag, so a result file always shows which kind of run made it.
